# VASPBERRY 1.6.0 — automatic spinor detection

VASPBERRY now detects scalar or two-component wavefunctions from WAVECAR.
Routine commands no longer need `-s`, `--spinor`, or Python component options.
The INI `spin_mode` is also optional.

```bash
make ifx-mpi
mpiexec -n 4 build/vaspberry-ifx-mpi --task kubo \
  --wavecar examples/1H-MoS2/KPATH/2.band/WAVECAR \
  --bands 1:18 --bundle 1 --curvature-csv KUBO.csv
```

This writes the supplied MoS₂ path's occupied-bundle curvature in Å².
For a full Hall scan, use the [Bi INI example](../../examples/features/simple-postprocess/)
and [postprocessing guide](../POSTPROCESSING.md).

## Compatibility

- Existing `-s 1|2` / `--spinor 1|2` commands remain valid. An explicit value
  must agree with the detected layout; conflicting values are no longer ignored.
- Detection checks coefficient counts against the full plane-wave basis at
  every k point and spin channel. Inconsistent or unsupported layouts stop
  before numerical work. Reduced Gamma-only files remain unsupported.
- WAVECAR-backed Python tools infer ordinary spin multiplicity where needed.
  The INI interface requires `collinear-up` or `collinear-down` for an ISPIN=2
  source, since selecting a channel is an analysis choice.
- Two-component storage does not establish whether SOC was enabled. The `soc`
  INI name remains a compatibility alias for `spinor`; matching OUTCAR is still
  used for PROCAR spin-frame information.

The original `-s` option controlled coefficient decomposition because the
WAVECAR ISPIN header alone does not distinguish scalar and spinor states.
Its role is retained as an optional check. Numerical formulas, output schemas
and historical reference tables are unchanged.
The Bi Z₂ comparator accepts the reviewed 1.6.0 producer while retaining the
original reference data and rejecting unreviewed producer versions.

This release also includes the MPI-help fix, public-input fetch retries and
the clarified VASPBERRY execution/postprocessing instructions since 1.5.0.
