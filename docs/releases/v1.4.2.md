# VASPBERRY 1.4.2

Released 2026-09-26. This compatible patch improves installation of the main
Fortran program and makes compiler changes produce the intended executable.
The numerical methods and output schemas are unchanged from v1.4.1.

## Native installation

The [README](../../README.md) now states the native requirements before the
commands: a Fortran compiler, GNU Make, POSIX tools and LP64 BLAS/LAPACK;
MPI adds a matching development wrapper and runtime. Native builds need
neither Python nor VASP. A source archive builds directly from its extracted
folder without Git; executables remain under `build/`.

The [build guide](../BUILD.md) provides Intel oneAPI/Intel MPI, retained
Intel Classic, GNU serial, Open MPI, MPICH and macOS instructions, with
explicit library paths and runtime setup. It distinguishes tested platforms
from WSL2 guidance and the limitations of fresh Homebrew installs on Intel
Macs. Users keep their preferred Python environment for later postprocessing.

```bash
git clone https://github.com/Infant83/VASPBERRY.git
cd VASPBERRY
make help
# Linux: load compiler, Intel MPI SDK and oneMKL, or equivalent site modules.
source /opt/intel/oneapi/setvars.sh
make check-ifx-mpi
mpiexec -n 4 build/vaspberry-ifx-mpi --help
```

For a fixed source, download this release's source archive and use the same
build commands inside it. Intel serial uses `make check-ifx`; GNU serial
uses `make serial check-serial-help`. See the guide for required packages.

## Makefile corrections

Environment compiler/wrapper/launcher settings are now respected. GNU Make's
built-in `FC=f77` no longer prevents the default from being `gfortran`.
GNU builds track their compiler command, flags and source selection, so
changing those settings cannot silently reuse an old executable. Failed GNU
compilations remove incomplete binaries; symlink build directories are rejected. Normal
unchanged builds remain incremental. `FFLAGS` and `LDFLAGS` provide additional
site flags; compiler-specific defaults keep preprocessing, extended fixed
lines, byte-based records and LP64 libraries.

`make help`, `check-ifx` and `check-ifort` make the available native paths
visible and provide serial checks without installing MPI. Existing targets,
output names and command-line interfaces remain available. Rebuild after
updating; changing the actual module/toolchain behind an unchanged command
name still calls for a fresh build directory or clean rebuild.

## Validation and scope

Publication requires thirteen successful jobs on this exact commit:
full CI, actual Bi serial/MPI, both Intel MPI compilers and two clean archive
installation jobs. The latter exercise GNU/MPICH on Ubuntu22.04 and
GNU/OpenMPI/OpenBLAS on macOS ARM64, including native help/runtime and
actual MoS₂ curvature/pair export. An incompatible Ubuntu24.04 MPICH
package was caught by the two-rank runtime check; the build guide documents
that package limitation and the tested Open MPI route for Ubuntu24.04. See the
[validation record](../VALIDATION_1.4.2.md).

The [technical report](../TECHNICAL_REPORT.md) ([PDF](../TECHNICAL_REPORT.pdf))
retains the same method edition and scientific figures. No new material
convergence or change in the canonical-momentum/projection interpretation
is implied by this installation patch. Previous release tags are unchanged.
