# MoS₂: VASP WAVECAR → Γ-point wavefunction and real-space density

This tutorial uses the **actual VASP MoS₂ files in this repository** to run
VASPBERRY's `-wf` command. It shows the raw real/imaginary spinor output and a
density figure calculated from those outputs.

## 1. Input files

Use these three files from the **same** VASP calculation:

| File | Purpose |
|---|---|
| [`WAVECAR`](../../1H-MoS2/KPATH/2.band/WAVECAR) | Plane-wave coefficients and lattice; 48 k points, 32 bands, SOC spinors, 400 eV. |
| [`POSCAR`](../../1H-MoS2/KPATH/2.band/POSCAR) | Species and atomic coordinates for the real-space file header. |
| [`EIGENVAL`](../../1H-MoS2/KPATH/2.band/EIGENVAL) | Header information used by the Fortran writer. |

The [material guide](../../1H-MoS2/README.md) links the VASP inputs. The stored
path is K → Γ → K′, with Γ present twice at one-based indices **24 and 25**.
This example chooses **band 18 at k index 24**, an occupied Γ state. These index
choices come from the actual WAVECAR; no model input or JSON configuration is used.

Input SHA-256 values:

```text
WAVECAR   33f8546512856d6c04ad0a80454b18ac9b60e2af4b98f2f85b376ec49b1a8d9f
POSCAR    3dcf3204cf3142453e7525a08026783e97887d2cb1bf05accdd770ac86c24d53
EIGENVAL  4632f93d56bb7bfc06414782faa752d10c347c66d95093631aed76412d71c2ae
```

The historical EIGENVAL title is a stale `PdTe2` label; the accompanying POSCAR,
WAVECAR lattice and documented dataset identify MoS₂. The original VASP output
is preserved unchanged.

## 2. Run VASPBERRY

From the repository root:

```bash
make serial
repo_dir="$PWD"
mkdir -p results
mkdir results/mos2-wavefunction
cp examples/1H-MoS2/KPATH/2.band/POSCAR results/mos2-wavefunction/
cp examples/1H-MoS2/KPATH/2.band/EIGENVAL results/mos2-wavefunction/
(
  cd results/mos2-wavefunction
  "$repo_dir/build/vaspberry-gfortran" \
    -f "$repo_dir/examples/1H-MoS2/KPATH/2.band/WAVECAR" \
    -s 2 -kx 48 -ky 1 -wf 18 -k 24 -ng 24,24,64 -im 1 \
    > stdout.log 2> stderr.log
)
python3 examples/features/wavefunction/run.py \
  --output-dir results/mos2-wavefunction --postprocess-only
```

The last command requires NumPy and Matplotlib. It reads both spinor components
of both real and imaginary grids, plots the density and compares the numerical
result with the reference. Its report records
`execution_mode=postprocess_existing_outputs` and `producer_revision=unknown`;
the current script/reader hashes identify the local analysis, not the executable
that produced existing grids. To automate the same steps in a fresh directory:

```bash
python3 examples/features/wavefunction/run.py \
  --output-dir results/mos2-wavefunction-replay
```

This automated mode records `execution_mode=calculate_and_postprocess`, the
executed command and binary hash, and the local Fortran source revision. The
shipped reference was generated by this mode.

| Flag | Meaning |
|---|---|
| `-s 2` | Two components of the SOC spinor. |
| `-wf 18` | Select the stored band number 18. |
| `-k 24` | Select the stored k-point index 24, Γ. |
| `-ng 24,24,64` | Real-space grid along the three cell vectors. |
| `-im 1` | Write the imaginary part as well as the real part. |

## 3. Outputs and expected result

| Output | Content |
|---|---|
| `PARCHG-W-K024-E018-SPIN1` | Real part; **two consecutive grids**, one for each spinor component. |
| `PARCHG-W-K024-E018-IM-SPIN1` | Imaginary part, also two grids. |
| `summary.csv` | z coordinate and plane-averaged density of each component and their sum. |
| `figure.png` | Density integrated along z and its plane-averaged z profile. |
| `result.json` | Inputs, checksums, command, Fourier reconstruction check and reference comparison. |

The raw `PARCHG-W` output contains **amplitudes**, despite its CHGCAR-like format.
With VASPBERRY's existing output convention,

```text
raw(r) = sqrt(V) * sum_G c_G exp(i G.r)
psi_pseudo(r) = raw(r) / V
rho_pseudo(r) = |psi_up(r)|^2 + |psi_down(r)|^2
```

Here `V = 130.6736745026 Å³`. The reference integrated pseudo-density is
**0.8258141586**, matching the stored coefficient norm **0.8258141556**.
This need not equal one: the plotted quantity uses the PAW pseudo-wavefunction
coefficients and does not include the PAW augmentation contribution. The helper
does not rescale it to one. It also checks the Fortran grids against a direct
Fourier reconstruction of the same WAVECAR coefficients (maximum observed error
**3.42 × 10⁻⁷ Å⁻³ᐟ²**, tolerance `1e-6`).

Reference files:
[numeric CSV](reference/summary.csv) · [provenance and checks](reference/result.json) ·
[raw amplitude grids](reference/raw-output.tar.gz) · [figure](reference/figure.png)

## 4. Apply this workflow to your material

Keep `WAVECAR`, `POSCAR` and `EIGENVAL` together from your calculation. Find the
actual Γ index and the band you want to visualize, then change `-wf`, `-k` and
`-ng`. The number of k points and spinor setting must match your files. The
helper accepts `--input-dir`, `--band` and `--k-index` for compatible SOC Γ data;
its z-profile plot requires an xy-plane slab with the third cell vector along
positive z. The direct CLI works independently of the helper.

Retain both real and imaginary parts and, for SOC, both spinor grids when forming
a density. A newly calculated WAVECAR can change the phase or basis inside a
degenerate manifold: individual amplitudes need not match this reference.
For comparisons across a degenerate subspace, sum the densities of all states
in that subspace. Choose a sufficiently fine real-space grid for your cutoff;
the tutorial helper checks whether its fixed grid can represent the stored G vectors.

The earlier synthetic Fourier check is retained under
[`validation/models/wavefunction`](../../../validation/models/wavefunction/).
